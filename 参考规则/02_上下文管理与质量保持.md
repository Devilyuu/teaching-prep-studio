# 上下文管理与质量保持

## 目标

避免随着聊天越来越长出现：

- 前期决策被遗忘
- 视觉风格漂移
- 页面越来越模板化
- 图片质量下降
- 已确认内容被重新讨论
- 后续课次重复前面已教内容

## 核心原则

> **质量存在文件里，不存在聊天里。**

## 默认规则

1. 一课一会话或一生产周期。
2. 课程级稳定信息写入《课程总控档案》。
3. 单课执行状态写入《单课进度档案》。
4. 每个阶段结束把产物落盘。
5. 下一阶段只加载必要文件。
6. 图片生成始终读取《视觉识别基准》和《视觉素材任务清单》；跨Agent生图时，这两份文件随任务包一起交接。
7. 每完成一课就归档，不在一个上下文连续生成整个学期全部PPT。
8. 使用质量样板课作为标准，不依赖模型"记得上次很好"。
9. 已定稿成果不重复生成。
10. 程序化渲染的源文件登记进《课程总控档案》的"课程素材源文件库"，新课次先读库再决定新做什么。

## 课程级素材源文件库｜V1.6 新增

备到第三、四课以后，程序化渲染的源文件（模拟产品的 HTML 基底、组件 CSS、课件页面版式脚本、截图脚本、token 表）会形成一套跨课次复用的资产。《课程总控档案》用 `课程素材源文件库` 登记，每条写：

- 源文件路径（相对课程根目录）
- 能渲染什么（如"学伴主界面 1440×900，可切干净 / 问题 / 揭示版"）
- 依赖（基底文件、token 表）
- 最后更新课次

规则：

1. 新课次**阶段 4 先读这个库**，再决定哪些图新做、哪些只改参数复用；
2. 新做的源文件在**阶段 11 归档时登记进库**；改了共用基底要写明影响哪些课次；
3. 课件页面版式脚本同样登记，后续课次只改内容不改版式；
4. 复用时沿用同一套 token / 识别基准数值，保证跨课次一致。

## 新会话最小加载集

- SKILL.md
- 课程总控档案.yaml
- 最新课程总纲
- 课程PPT视觉规范
- 质量样板课摘要
- 当前单课任务简报
- 跨课次续做时：上一课的《单课进度档案》（教师制作物料、课前待办、源文件）与《单课任务简报》（本课预告）

可选：上一课课后反思。

通常不需要加载上一课全部聊天记录。
