# 视觉素材生成器路由

## 目标

让备课流程不依赖某一个Agent是否具备生图能力，也不把所有图都交给生图模型。

## 判断顺序（每张素材单独判断）

0. **这张图能不能用代码精确画出来？** 能就程序化渲染，不走生图（V1.6 新增，见下）。
1. 当前Agent是否能原生生成图片？
2. 是否存在可自动调用的图像Skill/插件/工具？
3. 是否存在已授权、可直接回收结果的外部图像服务？
4. 都没有：生成一次性交接任务包。任务包只装真正需要生图模型的素材；程序化渲染与真实截图在本环境就地完成。

## 第0步｜程序化渲染（优先于一切生图判断）

### 适用

- 软件界面、网页、App 界面（含模拟产品的干净版、错误版、标注版）
- 图表、数据图、坐标图
- 结构性示意图：流程、架构、层级、区域划分、尺寸标注、对齐线、栅格
- 版式与排版示例、字阶与色板、组件规格卡、对照矩阵
- 代码、表格、终端截图
- 一切"数值必须精确、错误必须可控、多版本必须一致"的图

### 不适用（仍走生图）

场景、人物角色、材质质感、照片感、手绘插画感、需要想象力的意象图。

### 做法

1. 用 HTML+CSS / SVG / 图表库写源文件，放 `视觉素材/源文件/`；
2. 用无头浏览器截图（推荐 Playwright 驱动本机 Edge/Chrome，`device_scale_factor=2`），或 SVG 直接转 PNG；
3. 产出 PNG 放 `视觉素材/AI生成/`，清单里"来源方式"写"程序化渲染"，并登记源文件路径；
4. 一份源文件出多个版本：干净版 / 错误版 / 揭示版 / 区域版 / 尺寸标注版，靠参数切换，不重画；
5. 标注（编号框、连线、尺寸线）的坐标由 DOM 测量得出（如 `getBoundingClientRect`），不手填；
6. 渲染后逐张目检，按《04_视觉素材分类与生产规范》第七节验收。

最小示例（Python + Playwright）：

```python
from playwright.sync_api import sync_playwright
with sync_playwright() as p:
    b = p.chromium.launch(channel="msedge", headless=True)  # 本机 Edge；没有 Edge 就去掉 channel 用自带 Chromium
    pg = b.new_page(viewport={"width": 1440, "height": 900}, device_scale_factor=2)
    pg.goto("file:///…/视觉素材/源文件/xxx.html")
    pg.screenshot(path="视觉素材/AI生成/01_xxx.png")
```

### 同源导出

同一份源文件不只出图，还能导出：

- 规格表（每个元素的坐标、尺寸、颜色、字号、圆角、图层名）→ 教师在设计软件里复现起步文件的依据（E类，见《04》）；
- 数据表 / 标注坐标表 / 错误清单 → 学生任务书附件、找茬答案；
- 课件页面所需的裁切版、局部放大版。

导出的数值与课件里的图天然一致，学生手里的"找茬图"与"起步文件"不会对不上。

### 为什么排在生图前面

2026-09 UI 课四次备课实测：界面类素材用生图模型做不到"错误正好八处、坐标精确到像素、五个版本完全一致"，程序化渲染一次做到；组件 CSS 从第 3 课直接复用到第 4 课，新做一屏只用半小时（见《02_上下文管理与质量保持》课程级素材源文件库）。设计、编程、数据、办公软件类课程都适用。

## 真实界面截图（B类）

能驱动浏览器时，用脚本抓公开页面：固定视口（如 1440×900）、2 倍缩放、关闭弹窗；记录截图日期、登录/账号状态、是否含个人信息（须脱敏）。课件页注明"YYYY-MM-DD 截图 · 未登录空状态"之类的说明，防止学生把空状态当成产品全貌。

## 用户体验底线

禁止让教师逐条复制提示词。

无生图能力时必须交付完整ZIP/文件夹级任务包。

## 回流

收到"视觉素材完成包"后，自动核对任务编号、文件名、比例、一致性和教学用途，再从断点继续。
